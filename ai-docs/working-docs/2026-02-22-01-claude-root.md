# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

CIAM Claims PoC — a monorepo proving out Customer Identity and Access Management patterns with multi-tenant org-scoped claims processing.

Three workstreams, each with its own CLAUDE.md for workstream-specific guidance:
- **`ciam/`** — Bash scripts configuring Keycloak (Phase Two hosted) via Admin REST API
- **`claims-api/`** — Spring Boot 3.x REST API (Java 21, Gradle, Supabase PostgreSQL)
- **`claims-web/`** — Next.js frontend (TypeScript, Auth.js v5, Tailwind, shadcn/ui)

## Build & Test Commands

```bash
# Claims API (Spring Boot)
cd claims-api && ./gradlew test            # Run all 35 tests
cd claims-api && ./gradlew test --tests "*.ClaimControllerTest"  # Single test class
cd claims-api && ./gradlew bootRun         # Local dev server (port 8080)

# Claims Web (Next.js)
cd claims-web && pnpm test                 # Unit tests via Vitest (tests/unit/)
cd claims-web && pnpm exec playwright test # E2E tests via Playwright (tests/e2e/)
cd claims-web && pnpm dev                  # Dev server (port 3000)
cd claims-web && pnpm build                # Production build

# CIAM (Keycloak setup)
bash ciam/scripts/setup-all.sh             # Run all setup scripts
bash ciam/test/verify-setup.sh             # Validate configuration (37 checks)
```

## Architecture

### Token Flow (BFF Pattern)
```
Browser → Next.js (Auth.js/Keycloak OIDC) → encrypted session cookie
                    ↓
              Route handler → Spring Boot (Bearer token + X-Organization-Id header)
                                   ↓
                              Supabase PostgreSQL
```

Tokens never reach the browser. Auth.js stores them in an encrypted HTTP-only cookie. Server-side route handlers attach the token when calling the Spring Boot API.

### JWT Structure (Phase Two)
Phase Two tokens differ from standard Keycloak: no `sub` claim. The backend derives user UUID from email. Key custom claims:
- `organizations` — map of org UUID → `{ name, roles[] }`
- `org_attributes` — map of org UUID → `{ name, attributes: { accountNumber, contractTier, industry } }`
- `loyalty_tier` — user attribute (gold/silver/bronze)

### Org-Scoped Access Control
Every API request requires `X-Organization-Id` header. Spring Boot's `OrgContextFilter` validates the header against the JWT's `organizations` claim — returns 403 if the user isn't a member.

Role hierarchy per org: `admin` > `billing` > `viewer`.

### Key Security Files
- `claims-api/.../config/SecurityConfig.java` — JWT validation, CORS, filter chain
- `claims-api/.../config/JwtAuthConverter.java` — extracts orgs from token, builds authorities
- `claims-api/.../config/OrgContextFilter.java` — validates X-Organization-Id header
- `claims-web/auth.ts` — Auth.js config (jwt/session callbacks, token refresh)
- `claims-web/middleware.ts` — route protection
- `claims-web/src/lib/api.ts` — server-only API client (attaches Bearer + org header)

## Environment

All secrets in `.env` at repo root (gitignored). See `.env.example` for template.

**Local dev**: JDK 21 + Node 22 LTS directly (no dev containers). Dockerfiles are for CI/CD only.

**Critical env vars:**
- `AUTH_URL` — tells Auth.js its public URL (localhost:3000 locally, VM IP in production)
- `KEYCLOAK_ISSUER_URI` — shared by both apps for JWT validation
- `SUPABASE_JDBC_URL` — must use pooler host with `prepareThreshold=0`

## Public/Private Mirror

This is the **private** repo (`ciam-demo-private`). A filtered copy is published to `jackzhaojin/ciam-demo` (public). Keeping AI docs in a private repo with a clean public mirror lets agents load concise, relevant context instead of sifting through a bloated repo — shorter context means better AI output.

**What stays private** (excluded from public mirror):
- `ai-docs/` — all AI prompts, specs, strategy docs
- `CLAUDE.md` (all 4) — Claude Code instructions
- `.github/copilot-instructions.md`, `.github/copilot/` — GitHub Copilot config (if added)
- `AGENTS.md` — Codex/agent instructions
- `.claude/`, `.playwright-mcp/`, `local-only/` — local tooling
- `mirror-to-public.sh` — the sync script itself
- `.github/workflows/` — CI/CD lives on public only

**What syncs to public**: everything else (source code, configs, README.md, .gitignore, etc.)

**How to sync**: `./mirror-to-public.sh` replays new private commits to the public repo, skipping private-only commits. Use `--dry-run` first. It never auto-pushes — you run `git push` in `~/dev/ciam-demo` yourself. It also never mirrors tags; tags/releases are managed manually in the public repo.
Please read `./ai-docs/release-strategy.md` as well

**Key rule**: `README.md` is the public face. Put AI/agent instructions in `CLAUDE.md`, `AGENTS.md`, or `ai-docs/` — never in README.md.

## Deployment

GitHub Actions builds ARM64 Docker images (QEMU on x86 runners), pushes to GHCR, deploys via SSH to Oracle VM. Production env vars live in `.env` on the VM only.

- API: `ghcr.io/jackzhaojin/ciam-claims-api` → port 8080
- Web: `ghcr.io/jackzhaojin/ciam-claims-web` → port 3001 (mapped from container 3000)
- Both services report deployed version at `/api/health` (set via `APP_VERSION` build arg from release tag)
- Workflows live in the **public repo only** (`ciam-demo/.github/workflows/`)
